## React Server Component

- React v18 부터 새롭게 추가된, 새로운 유형의 컴포넌트
- 서버측에서만 실행되는 컴포넌트 (브라우저에서 실행 X)

### Page Router 버전에는 어떤 문제가 있었을까?

- 사전 렌더링 과정을 거쳐서 사용자에게 최종 렌더링이 된다.
- JS Bundle이 전달되면, hydration 을 통해 다시 렌더링이 된다.
- 상호작용이 없는 정적인 컴포넌트도 hydration 과정을 통해 다시 렌더링이 된다. (불필요한 과정 & bundle 파일의 사이즈 증가)
  - 즉, 상호작용이 없는 정적인 컴포넌트들을 JS Bundle 에서 제외시키는 것이 필요하다.
  - 이를 위해 추가된 개념이 Server Component 이다.

따라서, JS Bundle 에는 클라이언트 컴포넌트만 포함되도록 하는 것이 필요하다.

서버 컴포넌트: 서버 측에서 사전 렌더링을 진행할 때 딱 한번만 실행됨.
클라이언트 컴포넌트: 사전 렌더링 진행할 때 한번, 하이드레이션 진행할 때 한번. 총 2번 실행.

### App Router 에서의 Server Component

- 모든 컴포넌트는 기본적으로 Server Component로 인식한다.
  - 클라이언트 컴포넌트에서 사용 가능한 React Hooks 등을 사용하게 되면, error 가 발생하게 된다.
- Server Component 에서는 서버에서 동작하는 기능들을 사용할 수 있다.

서버 컴포넌트를 클라이언트 컴포넌트로 설정하고자 한다면, 파일의 상단에 `"use client";` 를 작성하면 된다.

상호작용이 필요하다면, 클라이언트 컴포넌트로 만들어야 한다.

- Link 는 html의 고유의 기능이므로, 상호작용이 아니다.

### React Server Component 주의사항

1. 서버 컴포넌트에는 브라우저에서 실행될 코드가 포함되면 안된다.
   - 클라이언트에서 동작하는 React Hooks, 이벤트 핸들러, 브라우저에서 실행되는 기능을 담고 있는 라이브러리 등의 코드가 포함될 수 없다.
2. 클라이언트 컴포넌트는 클라이언트에서만 실행되지 않는다.
   - 서버와 클라이언트에서 모두 실행된다.
   - `"use client";` 지시자를 사용하면 클라이언트 컴포넌트로 인식하여 총 2번 렌더링된다.
3. 클라이언트 컴포넌트에서 서버 컴포넌트를 import 할 수 없다.
   - 서버 컴포넌트의 코드는 오직 서버에서만 실행이 된다.
   - 브라우저에서 hydration을 위해 한번 더 렌더링이 될 때에는 서버 컴포넌트가 JS Bundle 에 포함되지 않기 때문에 "없다"고 인식한다.
   - 이런 경우 Next.js 는 자동으로 서버 컴포넌트를 클라이언트 컴포넌트로 변경한다.
   - 필요 시, 서버 컴포넌트를 children으로 전달하여 "클라이언트 컴포넌트로 자동 변경" 되지 않도록 한다.
4. 서버 컴포넌트에서 클라이언트 컴포넌트에게 직렬화 되지 않는 Props는 전달 불가하다.
   - 직렬화: 객체, 배열, 클래스 등의 복잡한 구조의 데이터를 네트워크 상으로 전송하기 위해 아주 단순한 형태(문자열, byte)로 변환하는 것.
   - 함수는 직렬화가 불가능하다. 즉, props로 전달 불가하다.
   - RSC Payload: React Server Component의 순수한 데이터 (결과물), 직렬화한 결과
     - 서버 컴포넌트의 렌더링 결과
     - 연결된 클라이언트 컴포넌트의 위치
     - 클라이언트 컴포넌트에게 전달하는 props 값
   - RSC Payload의 값과 클라이언트 컴포넌트를 합해서 사전렌더링을 진행할 때, 서버 컴포넌트에서 클라이언트 컴포넌트에게 직렬화가 불가능한 함수를 전달하려고 하면 에러가 발생한다.
